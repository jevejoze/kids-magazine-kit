# 栏目拆成可组合的 skill

依据：kit 的 ADR「栏目拆成可组合的 skill」（19 条决定）和开发计划。

## Problem Statement

家长现在出的这本杂志，栏目、页序、角色、周节奏全写死在引擎里。想加一个栏目、换个顺序、去掉周五轮换、换一套角色，都得改模板、样式表、校验库和讲读规则好几处，而且每处都牵连别的栏目。别的家庭 clone kit 以后，只能出一本和现有读者一模一样的杂志。各个 agent 做某一步时，要从一份很长的总规则里自己找哪些条目和这一步有关，容易漏，也容易撞题。

## Solution

每个栏目变成一个独立的 skill：自带写稿规则、字段 schema、校验、页面渲染、样式、讲读骨架和自己的状态。一本杂志由一份 `magazine.yaml` 决定出哪些栏目、按什么顺序、星期几出什么、用哪套角色和声音。确定性脚本按配置和日期算出本期要做的栏目和参数，agent 用任务单领一个栏目的活，任务单里正好是这个栏目要遵守的规则和要读的状态。下载图片、审稿、讲读、归档是共享能力。

切换过程对家长透明：数据仓库锁定引擎版本，日常出刊一直用旧版；新版在分支上逐个栏目迁移，每迁一个就和旧期逐像素比对；全部通过、试刊审稿通过后，在两期之间切过去。

## User Stories

1. 作为家长，我想在一份 `magazine.yaml` 里看到这本杂志出哪些栏目、什么顺序，这样我改编排时只改一个地方
2. 作为家长，我想调整栏目顺序后下一期就按新顺序出，这样我能按孩子的反馈试不同的阅读节奏
3. 作为家长，我想关掉一个栏目，下一期就不出这一页，讲读也自动跳过，这样我不用通知每个 agent
4. 作为家长，我想把周五轮换（音乐盒、放映室、动手做）写成编排里的一张表，这样我能自己排下周五出什么
5. 作为家长，我想在编排里写星期主题，这样调度脚本按日期给封面和今日一问定方向
6. 作为家长，我想把思维课表放进 `curriculum/`，由调度按周注入到真的假的和周末思辨，这样一份课表管两个栏目
7. 作为家长，我想页面和讲读里永远不出现"今天练什么"这类字眼，这样孩子只当是在玩
8. 作为家长，我想每个栏目的长期设定（小剧场的人物设定、连载书目）放在这个栏目自己的 `config.md`，这样我只改一个文件就能改设定
9. 作为家长，我想栏目的进度日志只追加、按期记录，这样我能回看哪一期发生了什么
10. 作为家长，我想一期定稿以后状态才变（伏笔、连载进度），这样被打回重做的稿子不会污染档案
11. 作为家长，我想日常出刊在重构期间完全不受影响，这样孩子每天照常有杂志看
12. 作为家长，我想在数据仓库里写一行 `engine.ref` 决定用哪个引擎版本，这样升级由我来决定
13. 作为家长，我想新引擎出问题时把 `engine.ref` 改回旧版就能接着出刊，这样切换没有风险
14. 作为家长，我想切换前看到全部旧期逐像素一致的报告，这样我相信迁移没改坏东西
15. 作为家长，我想迁移脚本先在副本上跑，结果满意再在正式数据上跑，这样不会误伤数据
16. 作为家长，我想反馈记录里的"最喜欢""不喜欢"存栏目 id，策展报告给我看时换回页名，这样换了页名也能连续统计
17. 作为家长，我想我转述"她最喜欢那页小剧场"时，agent 自己对照本期的页面清单换成 id，这样我照旧说人话
18. 作为家长，我想角色和声音都写在 `magazine.yaml`，密钥只放环境变量，这样配置可以安心放进 git
19. 作为家长，我想 `MY_CHILD.md` 保持原样、agent 只读，这样孩子的了解始终由我掌握
20. 作为出刊 agent，我想用一条命令拿到某个栏目的任务单（红线、声明的规则、角色映射、全局字段、参数、状态路径、上游值、输出路径），这样我不用在长文档里自己找规则
21. 作为出刊 agent，我想把任务单指纹写进输出，`check` 发现任务单变了就标过期，这样上游改了我能知道要重做
22. 作为出刊 agent，我想调度结果直接写在 brief 的 `sections` 里，这样我知道本期该做哪些栏目、各用什么参数
23. 作为出刊 agent，我想今日一问声明 `consumes: cover.question`，任务单里直接给我封面问题，这样两个栏目不会对不上
24. 作为出刊 agent，我想每个栏目在自己那一步下载图片到自己的目录，这样少一个全局的下载步骤，缺图在当步就能发现
25. 作为出刊 agent，我想栏目 manifest 声明图片授权策略，和杂志的 `image_policy` 对不上时直接报错，这样公开分享的刊不会混进有版权的图
26. 作为讲读 agent，我想渲染后有一份 `pages.json`（第几张卡是哪个栏目），这样讲读稿的卡号不再靠固定页序推算
27. 作为讲读 agent，我想每个栏目有自己的 `narrate.md` 骨架（主持槽位、句数上限、读哪些字段、哪些不念），这样我按页拼稿就行
28. 作为讲读 agent，我想句数上限按全期 10–12 分钟等比缩放，这样栏目多了少了总时长都合适
29. 作为审稿 agent，我想审稿读本期所有栏目声明的规则并集，再加上跨栏目撞题检查，这样审得全也不重复
30. 作为栏目作者，我想照一个标准目录（SKILL.md、manifest、schema、check、page.js、page.css、narrate.md）写一个新栏目，这样不用碰引擎代码
31. 作为栏目作者，我想 `page.js` 拿到一个 kit 对象（顶栏、页脚、角色、气泡、中文断行、目录、下页预告、cast），这样版式和别的栏目统一
32. 作为栏目作者，我想 `page.css` 的选择器被静态检查必须以 `#<skill-id>` 开头，这样我的样式不会串到别的页
33. 作为栏目作者，我想在 manifest 里声明参数的类型、默认值和范围，未声明的参数直接报错，这样配置写错能马上发现
34. 作为栏目作者，我想规则和校验里只写角色槽位（提问者、专家、英文担当、捣蛋鬼、旁白），这样换一套角色我的栏目照样能用
35. 作为栏目作者，我想在数据仓库的 `sections/` 里放自定义栏目，和引擎自带的同名时直接报错，这样不会悄悄覆盖引擎栏目
36. 作为第二个家庭，我想 clone kit、写一份不同的 `magazine.yaml`，就能出一本栏目、角色、节奏都不同的杂志，这样不用改任何引擎代码
37. 作为第二个家庭，我想只用两个角色、各兼几个槽位，这样小杂志也能跑通
38. 作为第二个家庭，我想关掉讲读，只出图片和 PDF，这样没有语音服务也能用
39. 作为引擎维护者，我想有一个回归脚本把所有目录格式的旧期渲染出来、和基线逐像素比对，这样每次改动都能证明没改坏
40. 作为引擎维护者，我想新旧渲染路径能并存（注册表里有的栏目走新路径，其余走旧模板），这样可以一个栏目一个栏目地迁
41. 作为引擎维护者，我想流水线的步骤表由注册表生成，这样加栏目不用手改步骤表
42. 作为引擎维护者，我想内容红线和 cast 包对所有栏目隐式生效、不能被声明掉，这样新栏目不会绕过红线
43. 作为引擎维护者，我想回归输出和试刊数据只留在本地或私有数据仓库，这样新闻原图和孩子的资料不会进公开仓库
44. 作为孩子，我想切换前后杂志看起来一模一样，这样每天的阅读不被打断

## Implementation Decisions

- **栏目注册表**：从引擎和数据仓库两处的 `sections/` 读出所有栏目；同名报错；按 manifest schema 校验（id、标题、consumes、params、rules、图片策略、讲读句数、状态声明）
- **栏目包**：标准 Agent Skill 格式。SKILL.md 带 frontmatter；manifest 声明元数据；schema 描述输出 JSON；check 导出按页校验（含按页讲读检查）；page.js 导出 `render(data, kit) => html[]`，可出多页；page.css 作用域固定在 `#<skill-id>`；narrate.md 写讲读骨架
- **一个 skill = 一种页面形态**：经典连载拆成连载书、音乐盒、放映室、动手做四个 skill；封面和今日一问分开
- **杂志配置**：`magazine.yaml` 装刊名、称呼、send_note、栏目列表与顺序、编排（星期主题、周五轮换）、cast、主题、image_policy、语音服务和各角色声音。引擎零依赖，配一个只支持 map、list、标量的子集解析器
- **调度**：确定性脚本输入 `magazine.yaml`、日期、课表，输出 brief 的 `sections`（出哪些、顺序、合并后的 params）。替代步骤表里的 `when`、`optional`
- **brief 三层**：编辑 agent 写全局字段；调度写 `sections`；栏目私有字段由各 skill 从自己的日志推出
- **参数**：manifest 声明类型、默认值、范围；合并结果放 `sections.<id>.params`；SKILL.md 正文引用，check 和 page.js 读同一个对象；SKILL.md 不做模板替换。首批只开放三项：周五轮换、image_policy、讲读句数上限
- **任务单**：流水线 CLI 新增 `ticket <issue> <skill>`，打印拼好的任务单并给出指纹；输出 JSON 的 `_meta.ticket` 记指纹，`check` 比对后标过期
- **规则**：总规则拆成独立的规则文件（红线、图片、英文档位、讲读、no-visible-pedagogy）；skill 在 manifest 里声明引用；红线和 cast 隐式包含；根 SKILL.md 只做路由
- **cast 槽位**：asker、expert、english、trickster、narrator；cast 包把槽位映射到具体角色，一个角色可兼多个槽位，最少 2 个角色；JSON 里照旧写具体角色
- **kit 对象**：从现有模板抽出共用版式函数，供所有 page.js 使用
- **混合渲染器**：注册表里有的栏目走 page.js + page.css，其余走旧模板对应段；页面尺寸由渲染器固定；渲染同时输出 `pages.json`。所有栏目迁完后删掉旧模板的栏目代码（expand–contract）
- **状态**：`state/<skill>/config.md` 家长编辑、`log.jsonl` 只追加；栏目输出里给状态变更（如小剧场的 `threads_after`），归档步骤落盘
- **图片**：各 skill 在自己那一步用共享下载模块下到 `20-assets/<skill-id>/`；第 20 步取消；manifest 的授权策略（`free-only` / `private-ok`）和杂志 image_policy 对照检查；折纸图式拆分成为动手做的私有逻辑
- **讲读**：整期稿仍由一个 agent 写；按 `pages.json` 和各栏目 narrate.md 拼骨架；句数上限按总长等比缩放；整期检查留在讲读能力里
- **审稿**：读已声明规则的并集，加跨栏目撞题检查
- **命名**：期内文件用 skill id 命名，去掉数字前缀；brief、review、narration、audio、video、archive 是保留名
- **反馈**：favorite、dislike 存 skill id，原话放 quote；旧记录随迁移一次性映射
- **版本锁定**：数据仓库的 `engine.ref` 写 tag 或分支；会话启动脚本 fetch 后检出该版本（分支再 fast-forward）；文件不存在时保持现有行为。kit main 当前状态打 `v1`
- **迁移**：一次性、可重复运行的迁移脚本：期内文件改名、反馈页名映射、四份 markdown 档案拆成各栏目的 config 和 log、profile 开头和 voices 配置并入 magazine.yaml、思维课表移入 curriculum；单文件旧期和 legacy 归档保持原样
- **打样顺序**：先小剧场（状态、四角色讲读、槽位），再经典连载（周五轮换、一拆四、图片自取）；之后其余栏目并行

## Testing Decisions

- 好的测试只看外部行为：给一个数据目录，跑流水线 CLI 和渲染，检查产出的 JSON、报错信息和页面像素
- **主接缝：流水线 CLI 跑在一个数据目录 fixture 上**。assemble、check、status、ticket、调度都从这里测。先例是现有的流水线测试：复制 demo 数据目录到临时目录、调 CLI、断言输出和报错
- **第二接缝：渲染输出的像素**。回归脚本对旧期逐像素比对，作为每个栏目迁移的验收；kit 的自动测试只用 demo fixture，真实旧期的回归在本地跑
- 渲染可复现先验证：同一引擎连渲两遍逐像素一致，才把像素比对当判据
- 需要 Chrome 的测试照现有做法按环境跳过
- 每个栏目 skill 的 check 用正例和反例 fixture 测（先例：挑战、今日一问、封面的字段与超长测试）
- YAML 子集解析器、manifest 校验、调度、任务单指纹、CSS 作用域检查、迁移脚本各有 fixture 测试
- 第二本杂志（改写后的 demo）从 brief 跑到 render 作为端到端验收：引擎代码零改动

## Out of Scope

- 多用户平台、账号、托管服务（等有第二个真实家庭、量过每期成本再定）
- 单文件格式的旧期和 legacy 归档的格式迁移
- 开放首批三项以外的参数
- 更换语音服务或视频合成方式
- 栏目内容规则本身的改写（只搬家、换成槽位措辞）

## Further Notes

- 重构期间日常出刊对引擎的修复先进 main，每周合进 `skills` 分支一次
- 回归基线含新闻原图，只放本地输出目录
- 试刊只在数据仓库的独立分支上做；切换放在两期之间
