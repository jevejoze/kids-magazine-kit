# 挑战（challenge）

每天一页，排在小剧场后面：捣蛋浣熊一句挑衅 + 一道四五年级奥数入门难度的题，和本期主题挂钩，唯一解。面向平板阅读，情境、条件和提问分开排版，不留手账、草稿和手写答案格。答案在本页底部倒印，不在下一期公布。周六、周日也照常出。

## 开工

1. 领任务单：`node scripts/pipeline.mjs ticket <issue> challenge`，照单上的规则、参数、角色槽位写，最后一行的指纹写进 `_meta.ticket`
2. 读 `issue/00-brief.json`
3. 写 `issue/14-puzzle.json`，字段见同目录 `schema.json`

```json
{
  "_meta": {"stage": "14-puzzle", "by": "", "at": "", "ticket": "<任务单指纹>"},
  "taunt_zh": "哼，数格子？我数得比蜜蜂还快！",
  "taunt_en": "Can you count faster than a bee?",
  "prop": "magnifier",
  "title": "🐝 谜题：一圈又一圈的蜂巢",
  "body": "简短说明题目情境、对象和规则。",
  "clues": ["条件一，每项只写一个条件，不手写编号。", "条件二，明确先后、数量或相邻关系。", "条件三，排除容易误解的说法。"],
  "question": "明确问孩子要得出什么结果，以及按什么顺序回答。",
  "answer": "① 18 个；② 37 个；③ 5 圈",
  "solution": "完整推导过程，并说明为什么答案唯一"
}
```

## 规则

- `taunt_zh` ≤ 20 字，嘴硬、挑衅、和题目有关；默认只显示中文，`taunt_en` 可省略，仅在明确启用英文三关时显示（≤ 10 个词）；`prop` 是浣熊的道具（见 cast 文档的角色写法，可空）
- 题型：4 个以上对象、3–4 条线索的逻辑排序；或需要两步以上推理的数学题
- `body` ≤ 120 字，只交代情境；`clues` 每条一个条件，模板自动编号；`question` 单独提出问题，明确队首/队尾、单位或回答顺序。情境、条件和问题合计 ≤ 240 字。新稿不写 `slots`。
- `answer` 是简短明确的最终答案，必须非空；`solution` 保留完整推导供审核，不全部塞进页底。英文三关默认暂停，本页以一道谜题为主；只有家长明确启用时才添加英文三关，其答案也在本页倒印。
- 旧稿只有 `body` 仍能渲染，但新稿必须按上述字段拆分。
- 排版按题目标题 → 情境 → 编号线索 → 明确提问阅读。标题写具体场景，不堆叠"谜题""挑战"等栏目名；线索每条只说一个条件，写清"前一位""紧挨着"等关系，避免把国家、人物背景等无用信息塞进题干。
- 难度：孩子要停下来想一想才能做出来；宁可偏难，题干里给一点提示托底。逻辑排序题照这三条出：
  - 每条线索都只缩小范围，没有一条直接写出某人在第几位
  - 去掉任意一条线索就不止一个解，每条都用得上
  - 至少要分两种情况试一次（"如果 A 在第 2 位……如果在第 3 位……"），`solution` 写出这一步
- 数学题至少两步，其中一步要倒着推或先求一个中间量
- 题目、条件和答案必须在平板卡片内完整显示；标准中文页的长题会自动收紧留白，题干与线索仍保持至少 30px 字号；渲染会拦截页脚或文字越界。不要用缩小到难读的字号容纳过长内容，先精简题干。

## 自检

`node scripts/pipeline.mjs check <issue>` 没有 `[14]` 报错；按 `solution` 自己从头做一遍；逻辑题把所有排列试一遍，确认只有一个满足全部条件，再逐条去掉线索，确认每次都不止一个解
